# Contributing to SharePoint SE ADFS WS-Federation Guide

Thank you for your interest in contributing to this guide! This document provides guidelines for contributing improvements, corrections, and additions.

## How to Contribute

### Reporting Issues

If you find errors, unclear instructions, or have suggestions for improvement:

1. Check if a similar issue already exists
2. Create a new issue with a clear description
3. Include:
   - What you expected to find
   - What you actually found
   - Suggestions for improvement (if any)
   - Your environment details (SharePoint version, ADFS version, etc.)

### Suggesting Enhancements

We welcome suggestions for:
- Additional configuration scenarios
- Improved troubleshooting steps
- Better script error handling
- New automation scripts
- Additional examples
- Performance optimization tips

### Pull Requests

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-feature-name`)
3. Make your changes
4. Test your changes thoroughly
5. Commit with clear, descriptive messages
6. Push to your fork
7. Submit a pull request

#### Pull Request Guidelines

- **Documentation changes**: Ensure proper formatting, clear language, and accurate technical details
- **Script changes**: Test scripts in a lab environment before submitting
- **Examples**: Verify examples work correctly
- **Follow existing style**: Match the formatting and structure of existing content

### Content Standards

#### Documentation

- Use clear, concise language
- Provide step-by-step instructions where appropriate
- Include code examples with explanations
- Test all commands and scripts
- Update table of contents if adding new sections
- Reference official Microsoft documentation where applicable

#### PowerShell Scripts

- Include comment-based help at the top
- Use parameter validation
- Include error handling
- Provide informative output
- Test thoroughly in lab environment
- Document prerequisites

#### Markdown Formatting

- Use proper heading hierarchy (H1 for title, H2 for main sections, etc.)
- Format code blocks with appropriate language syntax highlighting
- Use lists for sequential steps or multiple items
- Use tables for comparative information
- Use bold for emphasis on important terms

## Testing Your Contributions

### Documentation
- Verify all links work
- Check for typos and grammatical errors
- Ensure code blocks render correctly
- Test any PowerShell examples

### Scripts
- Test in a non-production SharePoint environment
- Verify error handling works correctly
- Ensure scripts follow PowerShell best practices
- Test with different parameter combinations

## Code of Conduct

### Our Standards

- Be respectful and inclusive
- Welcome newcomers
- Focus on constructive feedback
- Accept criticism gracefully
- Prioritize community benefit

### Unacceptable Behavior

- Harassment or discriminatory language
- Personal attacks
- Trolling or insulting comments
- Publishing others' private information
- Any conduct inappropriate in a professional setting

## Questions?

If you have questions about contributing, feel free to:
- Open an issue for discussion
- Review existing issues and pull requests
- Consult the main README.md documentation

## Recognition

Contributors will be acknowledged in the repository. We appreciate all contributions, no matter how small!
